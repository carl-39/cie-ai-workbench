# Prompt development

This function collection supports contributors who design, test and maintain reusable prompts for the workbench.

## Suggested route

1. Read the [Prompt engineering skill](../../skills/prompt-engineering/SKILL.md) to define inputs, outputs, constraints and verification.
2. Start a new contribution from the [prompt template](../../prompts/_template/README.md).
3. Review the [Research synthesis prompt](../../prompts/research-synthesis/README.md) as a worked experimental example.
4. Follow the [contribution workflow](../../docs/contribution-workflow.md) before proposing publication or a status change.

## Assets and resources

| Resource | Kind | Role in the work |
| --- | --- | --- |
| [Prompt engineering](../../skills/prompt-engineering/SKILL.md) | Skill | Provides a repeatable design and testing method. |
| [Prompt template](../../prompts/_template/README.md) | Template | Supplies the canonical structure and metadata fields. |
| [Research synthesis](../../prompts/research-synthesis/README.md) | Example prompt | Demonstrates bounded evidence use, variable inputs and verification requirements. |
| [Quality standards](../../docs/quality-standards.md) | Guidance | Defines cross-cutting expectations for responsible, verifiable assets. |

## Important boundary

A prompt is suitable for a bounded interaction. If reliable use depends on several human and AI responsibilities, contribute a pattern or a skill-supported agent instead of expanding one prompt indefinitely.
